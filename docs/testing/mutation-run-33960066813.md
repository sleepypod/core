## Verification and interpretation

- Full Vitest suite: **150 files passed; 3,693 tests passed, one skipped**.
- TypeScript and ESLint passed for the test changes.
- A fresh, non-incremental Stryker run against sleep-curve metadata, router OpenAPI metadata, and weekday/month constants killed **178/178 mutants**, with no survivors or timeouts. This includes seven additional endpoint metadata mutants outside the original candidate set.
- Every original candidate was considered for direct replay on current `dev`: substitute the reported source span in an isolated checkout, run the selected Vitest suites in a fresh process, then restore the source. Test selections use report coverage and corresponding unit-test filenames; focused follow-up replays use the corresponding unit suites. Each selected suite must pass without the mutation before its results are accepted.
- Where source moved, replay used an unchanged matching span. Changed spans are marked `SourceChanged`; they are not counted as killed. Direct replay tests executable behavior and does not duplicate Stryker's instrumentation, coverage selection, or TypeScript checking.
- `Killed` means the current tests rejected the mutation. Some were already detected by existing tests or intervening `dev` changes; these totals are **not** all improvements attributable to this patch. `Survived` means the selected suites passed, not a proof that the mutation is equivalent. The focused fresh Stryker result takes precedence for matching candidates.

Direct replay and focused Stryker overrides detected **690 candidates**: 319 from the completed reports and 371 from the database cache. **378 survived** (289 completed-report candidates and 89 cached database candidates); **13 source spans changed** and were not replayed.

### Remaining candidates

Several mutations preserve observable behavior: an empty explicit Drizzle column name falls back to the identical property key (89 database survivors); oversized `slice` bounds are clamped; redundant numeric guards still produce `NaN` or the same fallback; and some private initialization values are overwritten before use. Other survivors depend on defensive state predicates, lifecycle invariants, or uncommon exception paths. Their inventory notes identify the review rationale without declaring them all equivalent.

The remaining asynchronous pump/state-machine and streaming candidates deserve particular care: a passing selected-suite replay does not establish that every possible interleaving is safe. This patch adds regression tests for concrete reachable scenarios, and retains unresolved candidates in the inventory. It does not suppress mutants, weaken production guards, or assert a new whole-project mutation score. A complete CI mutation run, including the database shard, is still needed to measure that score.

### Reproduce the focused Stryker check

Create temporary config files in the repository root. `.mutation-review.vitest.mts`:

```ts
import base from './vitest.config.mts'
export default {
  ...base,
  test: {
    ...base.test,
    include: [
      'src/server/routers/tests/automations.crud.test.ts',
      'src/server/routers/tests/pumpAlerts.test.ts',
      'src/lib/sleepCurve/curvePrompt.test.ts',
    ],
  },
}
```

`.mutation-review.config.mjs` (line numbers refer to the reviewed base):

```js
import base from './stryker.config.mjs'
const routerLines = {
  automations: [74, 88, 99, 117, 136, 148, 160, 172, 182, 196, 228, 283, 315, 363, 543, 544],
  pumpAlerts: [56, 88, 124, 377, 439],
}
export default {
  ...base,
  mutate: [
    'src/lib/sleepCurve/types.ts',
    ...Object.entries(routerLines).flatMap(([file, lines]) =>
      lines.map(line => `src/server/routers/${file}.ts:${line}-${line}`)),
  ],
  checkers: [],
  incremental: false,
  concurrency: 2,
  vitest: { configFile: '.mutation-review.vitest.mts' },
  reporters: ['json', 'progress'],
}
```

Run `pnpm exec stryker run .mutation-review.config.mjs`, then remove the temporary configs. TypeScript is checked separately with `pnpm exec tsc --noEmit`.
