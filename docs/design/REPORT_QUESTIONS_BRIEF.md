# Questions about a saved report

Approved improvement 12: let a person ask follow-up questions about the same
saved evidence, with deliberate sharing. This extends the established morning
brief in Read/Operate mode. Preserve its type, blue accent, light/dark tokens,
owner shell and separate personal workspace; no new visual identity is introduced.

Place the question immediately after saved answers. Keep four understandable
states: compose, review destination and facts, wait/cancel, read the answer.
Saving an answer to the Pod is a separate explicit choice. Lost save replies
offer a read-back, never an immediate automatic upload. Account changes and hidden
pages clear the working copy and cancel pending requests.

Use the report's provider/model as the initial choice. Apple local generation
remains an iPhone capability with a clear handoff; never silently choose a cloud
provider instead. Browser-supported providers are OpenAI, Gemini, Anthropic and
an explicitly entered Ollama origin. Credentials are entered per request, held
only in memory, never embedded in the app, stored in browser storage or sent to
the Pod. The source page must be a secure context before credentials are entered.

Every review names its actual destination, model, source date, exact question and
expandable calculated facts. No recent Health records or earlier model prose are
added. Answers render through the existing escaped Markdown component and show
their generation date and model. Reading or generating cannot change bed controls.

Verify 390, 834 and 1440 widths, light/dark, keyboard focus, long copy, cancellation,
provider failure, lost save reply, account change and personal-only uploads.
Browser tests intercept provider requests with synthetic data; they do not prove
real key access, provider billing, remote HTTPS deployment or physical delivery.
