# Overnight explanation extension

Mode: Read within Tonight and temperature history. Preserve the incumbent visual
system, physical-side selector, typography and semantic colors. No new theme.

Answer “Why did it warm up?” and “Why did it stay cool?” using recorded controller
receipts, policy decisions and Pod temperatures. A compact disclosure opens an
ordered timeline for a selected wake date. Lead with the window and physical
zone, then requested/reported temperatures and concise events with expandable
source detail. Show room reports on the same clock without asserting they caused
a change. Keep missing sources, truncation and collection gaps visible.

A controller acknowledgment is not felt cooling. Preview is not an action.
Rule evaluation is not a hardware receipt. Repeated identical policy observations
may collapse only across short contiguous gaps; show count and endpoints.
Physical side is not personal identity. Existing housekeeping actions do not run
from this read-only view. The default date names the morning, with a Pod-local
noon-to-noon window including DST. A future date or stale failed refresh must not
silently display another date's evidence.

Verify narrow/wide web and phone/tablet renders, light/dark and large text, loading,
empty, partial/error, side/date switching and detail disclosures. Temperature
units follow app preferences. Retained history is not proof of continuous sleep
or complete controller uptime. House command receipts are a separate upcoming
integration; room sensor state cannot attribute who operated a device.
