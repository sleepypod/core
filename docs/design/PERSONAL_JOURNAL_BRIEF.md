# Personal morning check-in

## Scope and direction

Approved improvements 11 and 16 require a useful journal belonging to a person,
not a mattress side. This Operate surface extends the existing personal household
workspace. Preserve its cream/green light and dark palette, system controls,
typography, spacing and ordinary card structure. It is a code-led extension,
not a new visual world; no raster comp or new media asset is required.

## Task and first viewport

Within the check-in panel, lead with whose check-in this is, its wake date and
two explicit answers: restedness and temperature comfort. Notes and detailed
habit timing remain optional. The surrounding personal workspace keeps its
existing bed-control, history, learning and routine order. Opening or editing
a journal must not obstruct the independent Stop controls.

## Interaction contract

- Start ratings unselected and distinguish unlogged habits from explicit none.
- Keep private text in the open account-scoped view; clear it on hiding,
  sign-out, revoked access or changed assignment.
- Confirm discarding an unsaved draft when changing dates or closing.
- Save only after explicit submission, then read back the current entry.
- Reconcile a lost reply without resending; identify the loaded entry as an
  earlier snapshot while the outcome is uncertain.
- Review deletion explicitly and explain that existing backups/exports remain.
- Use labelled native controls, visible keyboard focus, status announcements,
  sensible focus after loading and responsive layouts at enlarged text sizes.

## Quality bar

The ordinary path needs two short answers and Save. Optional detail must not
compete with that path. A person should understand which date is open, whether
an entry is saved and how to recover from a failed read without interpreting
technical errors. At 390px and enlarged text there must be no horizontal
overflow, clipped control or inaccessible action. Tablet and desktop retain
legible, aligned fields without altering the established visual identity.

## Evidence boundaries

Browser fixtures are synthetic. Journal observations are subjective, not sleep
measurements or confirmed thermal effects. This surface never trains a model,
changes hardware, imports Health data or activates shared-bed arrangements.
Account isolation and stale-write behavior require contract/HTTP tests in
addition to rendered browser flows. Native parity and actual delivery remain
separate work in the platform implementation ledger.

## Habit-comparison extension

Keep the two-answer check-in path primary. After its editor, an optional
**Habits and feeling too warm** disclosure contains a bounded date range and one
explicit comparison action. It reads saved entries only, preserving the current
draft. Use the incumbent native date fields, typography, palette, focus states
and plain separated result rows; no new visual world or card grid.

A result leads with its source, selected range and read time. Within each retained
time zone, show usable and too-warm counts for both groups before the difference;
keep all group definitions and excluded counts available. Empty, insufficient,
loading and failed reads must remain distinct. A difference is an exploratory
association, never a causal claim or automatic bed adjustment. The existing
account/hide withdrawal and independent Stop behavior remain unchanged.

Required captures add desktop, tablet, phone/dark/enlarged text, empty,
insufficient-data and failed-read states to the existing journal evidence.
Fixtures must be labelled synthetic in the review packet. No external imagery,
new media asset or comp is required for this code-led extension.
